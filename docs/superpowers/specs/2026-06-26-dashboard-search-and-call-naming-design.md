# Поиск по диалогу + нейминг звонков в дашборде

**Дата:** 2026-06-26
**Ветка/воркспейс:** `multi-tenant-core-phase1` в `/root/projects/silentqa-dev`
**Статус:** дизайн утверждён на брейншторме (highlight-only поиск; нейминг = `metadata.title`, admin-only, колонка в списке); готов к плану реализации.

Спек A из пары. Пара B — `2026-06-26-scenario-driven-reevaluation-design.md` (#1 сценарная переоценка). Деление принято на брейншторме: A — две независимые точечные фронт-правки, B — фича через 4 слоя.

## Зачем

Юзер на тенанте `chechetov` смотрел свой созвон (`#call/<id>`) и отметил два пробела в дашборде:

1. **Поиск по диалогу** — в карточке звонка нет способа найти фрагмент в транскрипте (длинные созвоны не проскроллить глазами).
2. **Называть звонки** — звонок нельзя переименовать; в списке он опознаётся только по дате/телефону/менеджеру, в шапке карточки — захардкоженное «Сессия звонка».

Обе правки доменно-нейтральны (полезны любому тенанту), без новых таблиц и без миграций.

## #3 — Поиск по диалогу

### Текущее состояние (проверено)

- Транскрипт рендерится в `#transcriptContainer`: каждая реплика — `<div class="transcript-line" data-start data-end>` с детьми `.transcript-time` / `.speaker-tag` / `.transcript-text` (`backend/static/app.js:932-966`). Текст экранирован `escapeHtml` (`app.js:265-269`, `…959`).
- Аудио-синхронизация (`app.js:984-1018`): клик по строке → перемотка аудио на `data-start`; `timeupdate` при проигрывании → активной строке вешается класс `.transcript-line--active` + `scrollIntoView`.
- Существующий поиск `#callSearch` (`app.js:372`) — это фильтр **таблицы звонков** (`tr.style.display`, `…464-472`), к транскрипту отношения не имеет и не конфликтует.
- CSS: `.transcript-container` (скролл, `max-height`) и `.transcript-line--active` (левый бордер `#58a6ff` + фон) — `backend/static/styles.css:570-652`.

### Дизайн (highlight-only, как Ctrl+F)

Чистый клиент. Бэкенда нет.

**UI.** Над `#transcriptContainer` (внутри той же карточки «Транскрипт», после `<audio>`) — строка поиска `.transcript-search-box`:
- `<input>` «Поиск по диалогу…»;
- счётчик «N совпадений» / «нет совпадений» / пусто при пустом запросе;
- кнопки ↑ / ↓ (предыдущее/следующее совпадение) + (опц.) ✕ очистить.

**Подсветка.** Для каждого `.transcript-text`:
- источник — `el.textContent` (уже декодированный, безопасный);
- поиск — `indexOf` по `toLowerCase()` обеих сторон (**не RegExp** — чтобы спецсимволы `( [ . *` искались буквально и не было ReDoS);
- пересборка `innerHTML` из кусков: `escapeHtml(plain)` + `<mark class="transcript-match">escapeHtml(match)</mark>`. Совпадения вставляются **из заэкранированных подстрок** → инъекция невозможна.
- Текущее (активное навигацией) совпадение — доп. класс `.transcript-match--current` + `scrollIntoView({block:'center'})`.

**Навигация.** Состояние `{ query, matches: HTMLElement[], idx }`. ↑/↓ двигают `idx` по кругу, перевешивают `--current`, скроллят.

**Изоляция от аудио-синка.** Поиск трогает **только** классы `.transcript-match*` внутри `.transcript-text`. Класс `.transcript-line--active` остаётся за `timeupdate`-хендлером. Клик-перемотка не ломается (обработчик на `.transcript-line` не затрагивается; `<mark>` — потомок `.transcript-text`, клик всплывает к строке как и текст).

**Производительность.** Дебаунс ввода 200 мс. На пустой запрос — снять всю подсветку (восстановить исходный текст реплик) и обнулить счётчик.

**Идемпотентность (важно для безопасности).** При инициализации (`initTranscriptSearch`, на рендере карточки) **сразу** (эагерно, не лениво) сохраняем исходный текст каждой `.transcript-text` в `dataset.raw = el.textContent`. Перед каждым прогоном подсветки восстанавливаем через **`el.textContent = el.dataset.raw`** — НЕ `innerHTML` (иначе `<`/`>` в тексте распарсятся как теги → дыра XSS на самом шаге восстановления), чтобы не накапливать вложенные `<mark>`. Повторный рендер карточки пере-инициализирует чисто (слушатели на новых узлах, утечки нет).

**CSS (styles.css).**
- `.transcript-search-box` — fl.строка (input + кнопки + счётчик), отступ снизу.
- `mark.transcript-match` — фон-подсветка (на тёмной теме: `--warning`/янтарный с 25–30% прозрачностью, без потери читабельности), `color:inherit`, без съезда строки.
- `.transcript-match--current` — ярче (50%+) или `box-shadow`, чтобы отличаться от синей `.transcript-line--active`.

### Компоненты (изоляция)
- `initTranscriptSearch(container, inputEl, countEl, prevBtn, nextBtn)` — навешивает дебаунс-обработчик; держит локальное состояние.
- `highlightMatches(container, query)` → `HTMLElement[]` — чистит + подсвечивает, возвращает список `<mark>`.
- `gotoMatch(state, delta)` — двигает `--current` + скролл.
- `clearMatches(container)` — восстанавливает каждую `.transcript-text` через `el.textContent = el.dataset.raw` (никогда `innerHTML`).

Все — внутри `app.js`, без зависимостей от бэкенда.

### Edge cases
- Пустой/пробельный запрос → снять подсветку, счётчик пуст, строки не прячем.
- Спецсимволы запроса → буквальный поиск (`indexOf`).
- Кириллица `Ё/ё`: `toLowerCase` нормализует `Ё→ё`; для буквы `ё` vs `е` — это **разные** буквы, не схлопываем (как в браузерном поиске).
- Длинный транскрипт (500+ реплик) → дебаунс; при необходимости в будущем — подсветка только видимых через IntersectionObserver (вне scope MVP).
- Многословный запрос через границу реплик («привет мир» на двух строках) — **не** ищем кросс-строчно (MVP: совпадение в пределах одной `.transcript-text`); отметить как возможное расширение.
- Совпадение поверх активной строки — визуально сосуществуют (разные классы/цвета).

### Тесты
JS-тест-харнесса в репо нет. Верификация: `node --check backend/static/app.js` (синтаксис) + ручной чек-лист: пустой запрос; кириллица/спецсимволы; длинный транскрипт; клик по строке после поиска (перемотка работает); проигрывание при активном совпадении (классы не конфликтуют); очистка (все `<mark>` сняты, текст восстановлен).

### Вне scope
- Серверный полнотекстовый поиск по многим звонкам.
- Фильтр-режим (прятать не-совпавшие строки) — возможное будущее расширение, не MVP.
- Кросс-строчный/фразовый поиск через границы реплик.

## #4 — Называть звонки в дашборде

### Текущее состояние (проверено)

- У модели `Session` **нет** поля title/name — все доп-данные в JSON-колонке `metadata_` (`"metadata"`), `backend/app/models.py:22-37`.
- `SessionResponse.metadata` уже отдаётся во фронт (`backend/app/schemas.py:11-21`), `_to_response` прокидывает `metadata=session.metadata_` (`sessions.py:595-605`).
- Готовый паттерн мутации metadata: `PATCH /sessions/{id}/speaker-map` (`sessions.py:571-592`, `require_admin`, пишет `metadata["speaker_map"]`, возвращает `_to_response`).
- Список звонков: 8 колонок (Дата/Источник/Шаблон/Телефон/Менеджер/Длительность/Статус/Чанки), `app.js:376-402`; пустое состояние `colspan="8"`.
- Шапка карточки: захардкоженный `<h1>Сессия звонка</h1>` (`app.js:565`).

### Дизайн (без миграции)

**Хранение.** `metadata.title: str` — как `phone`/`employee`/`source`. Ноль миграций.

**Бэкенд.** Новый эндпоинт по образцу speaker-map:
```
PATCH /api/sessions/{session_id}/title      dependencies=[require_admin]
body: { "title": str | null }
```
- Pydantic `TitleUpdate { title: str | None = None }`.
- Сервер: `title = (body.title or "").strip()`; если пусто → `meta.pop("title", None)` (очистка); иначе `meta["title"] = title[:200]` (лимит 200; ср. `_EMPLOYEE_MAX_LEN`).
- Возвращает `SessionResponse` (через `_to_response`) — `metadata.title` доезжает обратно во фронт.
- Статусы: 200 ok; 404 — нет сессии; 401 — без сессии; 403 — не admin. Переименование разрешено в **любом** статусе сессии (title — чистая metadata, на пайплайн не влияет; в отличие от reprocess, который блокируется на `processing`).
- Без HTML-санитайза на бэке (хранится как есть); защита от XSS — `escapeHtml` на рендере.

**Фронтенд.**
- *Шапка карточки* (`<h1>` на `app.js:565`, внутри `.call-detail-header`/`.call-detail-meta`, `558-593`): вместо статичного `<h1>` — заголовок из `metadata.title`; фолбэк (нет title) — «Сессия звонка». Замена остаётся **внутри** существующего template-literal (строковая конкатенация) — не сломать JS-синтаксис. Рядом (только `isAdmin()`) — кнопка-карандаш → инлайн-`<input maxlength="200">` → `PATCH …/title` → обновить заголовок и кеш сессии. `escapeHtml` обязателен.
  - **UX-контракт инлайн-редактора:** сохранение по Enter или blur; отмена по Escape (вернуть прежнее значение); при ошибке PATCH — тост + откат отображаемого заголовка к прежнему. (Паттерн как у инлайн-редактора имени спикера в этом же коде.)
- *Список* (`app.js:376-402`): добавить колонку «Название» (после «Дата»): `escapeHtml(s.metadata?.title || '—')`, CSS `text-overflow:ellipsis` + `max-width`. Поднять `colspan` пустого состояния 8 → 9, добавить `<th>` и `<td>`. Побочный эффект (желательный): существующий фильтр `#callSearch` (`tr.textContent`) после добавления колонки начнёт искать и по названию — оставляем как есть.
- Видимость: title видят все роли; карандаш-редактор — только admin.

### RBAC
**Admin-only.** `PATCH …/title` гейтится `require_admin` (как speaker-map). Но `title` живёт в `metadata`, а её клиент задаёт при `POST /api/sessions` — чтобы PATCH был **единственным** путём записи, добавить `"title"` в `_SERVER_OWNED_METADATA` (`backend/app/routes/sessions.py`), тогда `build_session_metadata` срежет клиентский `title` на создании. Иначе любой ingestion-клиент (расширение/десктоп/API-key) сможет проставить название в обход admin-гейта. Менеджерский self-rename (через `require_session_access`) — возможное расширение позже.

### Edge cases
- Пустой/пробельный title → очистка (ключ удаляется из metadata).
- Длинный (200+) → обрезка до 200.
- HTML/скрипт в title → хранится как текст, рендерится через `escapeHtml` (юзер увидит литерал, не исполнение).
- Очень длинный в списке → ellipsis + max-width.
- Конкурентные переименования → last-write-wins (как у speaker-map/link-lead; без блокировок).
- Сохранность прочих metadata — обязательно (берём `dict(session.metadata_ or {})`, меняем только `title`).

### Тесты
`backend/tests/test_session_title.py`. `FakeRedis` берётся из `conftest.py` (фикстура `fake_redis`); override `get_db` тест-файл задаёт **сам** через локальный `_FakeDB` + `app.dependency_overrides[get_db]` (паттерн из `test_desktop_template_gate.py:31-83`, не из conftest):
- `test_admin_rename_ok` — PATCH admin-кукой → `metadata.title` в ответе и доезжает на GET.
- `test_clear_title` — **параметризовать** по `{title:null}` / `{title:""}` / `{title:"   "}` → во всех случаях ключ `title` отсутствует.
- `test_truncate_200` — 500 символов → обрезано до 200.
- `test_preserves_other_metadata` — у сессии есть `phone`/`employee` → они сохраняются.
- `test_unauthorized_401` — без куки → 401.
- `test_viewer_403` — viewer-кука → 403.
- `test_manager_403` — manager-кука → 403 (отдельная роль/auth-путь; паттерн куки — `test_manager_scope.py`).
- `test_not_found_404` — случайный uuid → 404.
- `test_title_stripped_on_create` — `POST /api/sessions` с `metadata.title` → на сессии `title` отсутствует (т.е. `_SERVER_OWNED_METADATA` срезала клиентский title; PATCH — единственный путь записи).

### Вне scope
- Поле-колонка `title` в БД (миграция) — только если позже понадобятся сортировка/фильтр по названию.
- Автогенерация «умного» заголовка по умолчанию.
- Менеджерский self-rename.
